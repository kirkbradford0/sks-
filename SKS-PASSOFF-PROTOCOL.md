# SKS CONTEXT PASSOFF PROTOCOL (Kirk order, 2026-09-18)

Kirk: "When in doubt the SKS repo is available for an MD file passoff or
even when you need contextual space." Discord comes later, eased into —
the repo is home base, not the board.

## The rule
When a session's context is filling up or a thread of work outgrows the
conversation, PASS OFF to sks- as a dated markdown file. Do not compress
into oblivion, do not force the work into Discord, do not lose state.

## How to pass off
1. File: `SKS passoff <topic> YYYY-MM-DD.md` in sks- root (or append to
   the existing handoff for that day if the topic matches).
2. Contents: what was decided, what's done (with commit SHAs), what's
   open, and the exact next action. Write it so a fresh session with zero
   memory can continue cold.
3. Commit + push before the session ends. Uncommitted passoff = no passoff.
4. Link it from `SKS running tasks list.md` if it creates open work.

## Discord posture (revised)
- Discord is a VIEW and eases in on Kirk's schedule — not a destination
  for state. Repository of truth: sks- (state) + dabs (claims).
- Muse's culture layer for the board still stands, but the board mirrors
  repo content; it never replaces it.
- No seat should ever say "it's in Discord" — if it isn't committed to
  sks- or dabs, it doesn't exist.

Kirk holds veto on all of the above.
